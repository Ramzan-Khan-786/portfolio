# Version 1 — engineering portfolio

Current package version: **1.1.0**, an enhancement of the original V1 foundation, not a V2 feature release.

## Implemented

Responsive public profile, skills, work catalogue/details, about/contact, shared footer/socials, real route navigation, simple CMS text pages, and an independent-application showroom. The CMS controls profile/CTAs, skills, projects, showroom, navigation, pages, links, and metadata/settings.

The showroom has CMS defaults/order/visibility, accessible tabs, directional transitions, Coming Soon, actual iframe integration, loading/reload/help, and external opening. There is no locally simulated TypeWriter product.

The backend has admin-only content APIs, cookie JWTs with server-side role/session-version checks, revocation/password changes, validation, rate limits, origin defenses, safe errors, and insert-only seeding. Automated unit, real-database integration, and browser flows are included.

## Explicit limitations and remaining deployment work

- Supply and verify the actual embedding-compatible TypeWriter URL.
- Review personal seed copy, resume/images, contact address, and social destinations before publishing.
- Provision the live database/hosts, HTTPS/routing, secrets, backups, and origin/cookie configuration.
- Validate the real TypeWriter application and target browsers/devices, not just the controlled integration fixture.
- Client-rendered metadata and 404 views are not SSR or server-status-aware SEO.
- No public registration/reset-email/MFA, uploads, realtime CMS notifications, distributed rate limits, blog, AI, or analytics pipeline.
- Automated tests are evidence for implemented contracts, not an independent security audit or production SLA.

Existing CMS records/passwords are preserved. Legacy sandbox values resolve to iframe; older tokens require login again. No automated verification modifies your configured content database. See [latest QA evidence](../QA_REPORT.md).
